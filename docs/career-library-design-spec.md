# 求职资料库设计规范

> 状态：已确认的开发基线  
> 日期：2026-08-13  
> 范围：首版只统一管理系统已经持久化的生成成果，不改变成果的生成逻辑。

## 1. 目标

把目前散落在简历、JD 匹配和面试助手页面右上角的历史成果，集中到一个结构清晰的“求职资料库”。资料库提供两种查看方式：

- **按岗位**：把同一岗位相关的岗位分析、定制简历、面试准备和模拟面试/复盘收在一个岗位档案中。
- **按分类**：把全部成果按简历成果、岗位分析和面试资料分组展示。

两种方式只是同一批数据的不同组织视图，不创建副本，也不改变原始数据的归属。

## 2. 已确认的核心规则

1. 主导航新增“求职资料库”，放在“投递岗位跟进”之后、“设置”之前。
2. “按岗位”和“按分类”都是资料库列表页，保留录阶的全局侧栏和顶栏。
3. 两种列表页使用**完全相同的资料卡片组件和卡片图形**：
   - 相同尺寸、封面比例、边框、间距、标题区、元数据区和操作位置。
   - 统一使用录阶现有的中性文件/档案图形，不根据“岗位分析”“面试资料”等类型另画图表、对话框或书本样式。
   - 类型差异只通过标题、标签、关联岗位、更新时间和内容摘要表达。
4. 点击岗位卡片或成果卡片后，进入类似简历编辑器的独立全屏工作区。
5. 独立工作区隐藏全局侧栏和全局顶栏，只保留：
   - 顶部工作区工具栏；
   - 一层左侧资料树；
   - 一层右侧正文区。
6. 不允许出现“全局侧栏 + 内部资料树”的双层侧栏，也不把资料树套在第二层面板中。
7. “通用”不是资料类型，而是资料与岗位的关联范围：
   - 通用简历优化属于“简历成果 / 通用优化”，不关联岗位；
   - JD 优化简历属于“简历成果 / 岗位定制”，关联一个岗位；
   - 不设置“通用资料”分类或占位卡片。

## 3. 首版纳入范围

| 用户看到的成果 | 分类 | 岗位关系 | 首版处理 |
| --- | --- | --- | --- |
| 通用简历优化 | 简历成果 / 通用优化 | 无 | 纳入 |
| JD 定制简历 | 简历成果 / 岗位定制 | 有 | 纳入 |
| 原始 JD | 岗位分析 | 有 | 纳入；资料库不把自动提取的关键词、要求、风险和建议作为独立档案 |
| 面试准备资料 | 面试资料 / 面试准备 | 有 | 纳入 |
| 模拟面试、回答与 AI 复盘 | 面试资料 / 模拟面试与复盘 | 有 | 纳入 |

首版不纳入：

- 原始简历：它不是系统生成成果，继续由简历编辑器管理。
- 投递记录和跟进日志：它们属于求职流程状态，不是资料成果。
- 求职信、招呼语：当前只保存在弹窗组件状态中，刷新或关闭后不会持久化；在增加正式保存能力之前，资料库不得展示虚假入口。
- 导出的 PDF、DOCX：导出文件是下载结果，不在资料库中再次保存一份。

## 4. 信息架构

### 4.1 资料库列表页

顶部结构固定为：

1. 标题“求职资料库”；
2. 说明“按岗位或分类整理你的生成成果”；
3. “按岗位 / 按分类”分段切换；
4. 搜索；
5. 资料分类筛选（全部资料、岗位分析、简历成果、面试资料）；
6. 网格/列表视图切换；
7. 资料卡片内容。

默认进入“按岗位”，用户切换视图后可在当前会话中保留选择。

### 4.2 按岗位

每张卡片代表一个岗位档案，而不是一条新的数据库记录。卡片至少显示：

- 公司与岗位名称；
- 当前投递阶段（存在投递记录时）；
- 最近更新时间；
- 岗位分析、定制简历、面试准备、模拟面试的数量。

只有至少包含一项已持久化生成成果的岗位才进入资料库。卡片主体整体可点击；首版不提供“删除整个岗位档案”，避免误删岗位、投递和面试数据。

岗位列表按公司形成视觉分组。同一公司的不同岗位仍保留独立岗位卡片，不合并岗位数据；公司识别只使用高置信度名称归一化，例如忽略空格、标点以及“有限公司”“Co., Ltd.”等法人后缀，不能仅凭名称前缀相似就强行合并。

### 4.3 岗位档案工作区

进入岗位后采用独立全屏工作区：

- 顶部：关闭、岗位名称、状态、关联简历、导出、添加资料等操作；
- 左侧资料树：固定展示“岗位分析 / 简历成果 / 面试资料”三个一级分类，让档案结构始终清晰；三个分类默认收起；
- 右侧：显示当前选中节点的正文。

建议树结构：

```text
岗位档案
├─ 档案概览
├─ 岗位分析
│  └─ 原始 JD
├─ 定制简历
│  └─ {定制简历名称}
├─ 面试准备
│  └─ {准备资料名称}
└─ 模拟面试与复盘
   ├─ {第 N 次模拟}
   └─ {对应复盘，存在时}
```

三个一级分类即使暂时没有成果也必须保留，并在分类内显示简短的“暂无资料”说明；分类下的具体成果和成果内部节点仍只根据真实数据生成，不能补造不存在的内容。

### 4.4 按分类

按分类页与按岗位页使用同一外层布局和同一资料卡片，不使用二级管理面板。内容按标题分段：

1. **简历成果**
   - 通用优化；
   - 岗位定制。
2. **岗位分析**
3. **面试资料**
   - 面试准备；
   - 模拟面试与复盘。

每个分段显示分组标题、数量、“查看全部”和成果卡片。“查看全部”只应用分类筛选，不进入树状工作区；点击具体成果卡片才进入成果工作区。

### 4.5 成果工作区

成果工作区与岗位档案使用相同的全屏框架，但左侧树只描述当前成果自身的结构。

#### 通用简历优化

```text
优化资料
├─ 优化概览
├─ 简历诊断（有诊断数据时）
│  ├─ 诊断结论
│  ├─ 已有优势
│  └─ 问题清单
├─ 优化后简历
└─ 修改记录（有记录时）
   ├─ 个人简介
   ├─ 工作经历
   ├─ 项目经历
   └─ 技能
```

#### JD 定制简历

```text
定制资料
├─ 优化概览
├─ 岗位关联
├─ 优化前简历
├─ 优化后简历
└─ 修改对比
```

#### 原始 JD

```text
原始 JD
```

#### 面试准备

```text
面试准备
├─ 能力画像
├─ 证据与差距
├─ 核心知识
├─ 经历深挖
├─ 针对性问题
├─ 准备计划
└─ 自我介绍与反问
```

#### 模拟面试与复盘

```text
模拟面试
├─ 模拟概览
├─ 问题与回答
│  ├─ 问题 1
│  └─ 问题 N
└─ AI 复盘（已完成且存在反馈时）
```

历史记录缺少诊断、修改记录或复盘时，目录只显示真实存在的内容，不能推测或补造。

## 5. 卡片规范

所有岗位卡片和成果卡片共享一个视觉骨架：

- 桌面网格默认两列；列表模式只改变布局，不改变信息层级。
- 卡片顶部使用同一套低对比度档案封面图形。
- 卡片正文依次为标题、类型/状态、关联岗位（如有）、更新时间、内容摘要或数量。
- 卡片主体是主要打开入口；删除等危险操作放入更多菜单并要求确认。
- 不为资料类型增加独立彩色主题、不同封面插画或不同卡片结构。
- 不使用大面积渐变、玻璃效果、厚阴影和卡片套卡片。

## 6. 搜索、排序和状态

- 搜索范围：成果名称、公司、岗位、资料类型和摘要；不在首版对长正文做全文索引。
- 默认仍按最近更新时间展示；岗位档案的更新时间取其全部成果中的最大值。列表右侧不再单独提供排序下拉，而是提供资料分类筛选。
- 空状态区分：完全没有成果、当前分类为空、搜索无结果。
- 数据被其他页面删除后，资料库立即反映；深链接指向已删除记录时显示“资料不存在或已删除”，并提供返回资料库。
- 加载失败不能回退为伪造样例数据。

## 7. 响应式行为

- 桌面端：完整全局侧栏；列表两列；工作区固定资料树。
- 平板端：卡片可降为一列；资料树允许收窄。
- 手机端：沿用现有移动顶栏；工作区资料树收进抽屉，正文保持单列，不同时挤压显示树和正文。

## 8. 入口迁移

资料库上线后：

- 移除页面右上角用于浏览全部优化版本、面试资料和面试记录的历史下拉入口。
- 各生成流程完成页保留与当前任务直接相关的操作，例如“查看本次成果”“进入编辑器”“前往资料库”。
- 不同时维护两套完整历史列表，避免用户继续面对重复入口。

## 9. 验收清单

- [ ] “求职资料库”位于“投递岗位跟进”之后。
- [ ] 按岗位和按分类列表使用同一资料卡片及同一封面图形。
- [ ] 按分类页只有分组标题和卡片，没有内部侧栏。
- [ ] 岗位与成果详情隐藏全局侧栏和顶栏。
- [ ] 详情页只有一层资料树和一层正文。
- [ ] 通用优化归入“简历成果 / 通用优化”，不出现“通用资料”。
- [ ] 同一成果不会因为两种查看方式而产生两份数据。
- [ ] 历史记录只显示实际存在的结构化内容。
- [ ] 当前未持久化的求职信和招呼语不进入资料库。
